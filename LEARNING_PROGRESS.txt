№40. Запись во временный файл и атомарная замена — ПРИНЯТО

По concept-coach объяснить нужные новые API до кода, но не вводить новые библиотеки,
классы-обёртки, интерфейсы, стратегию fallback или систему миграций.
Мини-урок:
- Path.toAbsolutePath возвращает абсолютный путь. getParent возвращает родительский
  путь без проверки существования. У saved.txt относительный getParent может быть null;
  брать родителя после toAbsolutePath. У корня C:\ родителя всё равно нет.
- Files.createTempFile(parent, ".taskmanager-", ".tmp") действительно создаёт новый
  пустой файл с уникальным именем в существующей указанной папке и возвращает Path.
  Он не удаляется автоматически. Выбрать папку целевого файла, не системную TEMP.
- BufferedWriter буферизирует символы; close сначала сбрасывает буфер и тоже может
  выбросить IOException. try-with-resources закрывает его. Move только ПОСЛЕ успешного
  выхода из внутреннего try-with-resources; Properties.store сам writer не закрывает.
- StandardCopyOption — enum (набор именованных опций). Files.move(temp, target,
  StandardCopyOption.ATOMIC_MOVE) просит атомарную операцию файловой системы.
  При этой опции остальные игнорируются; замена существующего target зависит от
  реализации. Если атомарность недоступна, отказать с исключением, НЕ делать обычный move.
  Это не отдельная гарантия сохранности при выключении питания. На локальной системе
  наставник отдельно проверил успешную атомарную замену в собственном временном каталоге.
- Files.deleteIfExists(temp) удаляет temp, возвращает false если его уже нет и
  может выбросить IOException. После успешного move исходного temp уже нет.
- Throwable.addSuppressed позволяет сохранить вторичную ошибку рядом с основной:
  writeError.addSuppressed(cleanupError). Она не заменяет cause или основную ошибку;
  затем throw writeError. Не терять ошибку записи из-за ошибки очистки в finally.
