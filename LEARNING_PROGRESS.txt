Цель: самостоятельно писать понятный, рабочий код и освоить практики командной разработки.
Формат: одно небольшое задание → самостоятельная реализация → ревью.
После приёмки сразу выдаётся следующее задание. Ментор обновляет этот журнал.
Рутинные операции с импортами и форматированием можно автоматизировать.

сравнение объектов и использование исключений для обычного ветвления.
Результат: корректная реализация; тест завершения использует ID, отличный от 1.

№2. Переименование задачи — ПРИНЯТО
Сделано: Task.rename, общая валидация названия, сохранение состояния при ошибке.

Замечание: названия тестов должны описывать ожидаемое поведение.

Результат: тесты проверяют возвращаемое значение и состояние объекта.

№5. Первый локальный Git-коммит — В РАБОТЕ
Цель: научиться фиксировать проверенное состояние проекта и выбирать файлы коммита.
1. Инициализировать Git в корне TaskManager.
2. Добавить в .gitignore правило /.idea/; правило target/ уже есть.
3. Подготовить первый коммит: src/, pom.xml, .gitignore, LEARNING_PROGRESS.txt.
4. Перед коммитом просмотреть git status и git diff --cached.
5. Создать коммит с сообщением: Add task manager with tested task operations
Критерии: коммит содержит исходники, тесты, конфигурацию Maven, .gitignore и журнал;
в нём нет target/ и .idea/; после коммита рабочее дерево чистое.
Публикация на GitHub не требуется.
Проверка: история и содержимое коммита, правила игнорирования, git status.
